# How it works

## Phase 0 — Application skeleton

Spring Boot starts the web server and wires the application components together.
The Maven Wrapper gives every developer the same Maven version; Java 21 is still required.
PostgreSQL runs separately in Docker and keeps its data in a named volume.
Configuration comes from application.yml, with environment variables overriding defaults.
Passwords come from the environment, while .env is ignored by Git.
The UTC Clock bean gives future services a replaceable source of Java-side time.
Actuator health reports whether the application and its database connection are healthy.
The key concept: the application is disposable; durable state belongs in PostgreSQL.

## Phase 1 — Persistence

Flyway applies V1 to create jobs and V2 to create job_runs before Hibernate starts.
Flyway records applied versions and checksums; change the schema with a new migration.
Hibernate validates the schema instead of creating or modifying it.
JSONB stores executor-specific payloads; string enums make statuses readable in SQL.
Instant maps to timestamptz, so a timestamp represents the same moment in any timezone.
The job's version column lets JPA reject an update based on an outdated copy.
Created/updated audit timestamps are generated by PostgreSQL for JPA writes.
Run history stores a job ID; PostgreSQL's foreign key removes history when the job is deleted.
The partial due index contains ACTIVE jobs; the history index supports newest-first lookups.
The key concept: migrations own the schema; JPA maps it and detects stale CRUD writes.

## Phase 2 — REST API and schedule calculations

JobController accepts validated request records; responses never expose JPA entities or lease ownership.
JobService changes database state inside transactions and flushes before returning the new version.
A PUT includes the version you read; a stale version returns 409 instead of silently losing an edit.
ScheduleCalculator uses Spring's six-field cron parser with the job's timezone and returns an Instant.
In New York, a 02:30 cron skips the spring DST gap; a 01:30 cron can occur twice during the fall overlap.
Fixed-rate schedules start one interval from the reference time; one-time schedules preserve runAt.
Pause is idempotent, resume recalculates due time, and trigger uses PostgreSQL now() to mark the job due.
The HTTP payload validator checks configuration without making requests; execution comes in Phase 3.
ProblemDetail gives clients a consistent error format, including field names for validation failures.
The key concept: an API request saves intent; a worker will later claim and execute that intent.
